# RoomLoom

RoomLoom rebuilds a place, remembered, planned or imagined, from a sketch, old photos and conversation with an AI agent, as a walkable 3D model in the browser.
Use `RoomLoom` as the display name and `roomloom` for packages, folders and identifiers.

## Current state

The repo scaffold (task T01), the scene schema (task T02) and the project store with history and photo uploads (task T03) exist so far. The backend serves projects over a REST API (see [Projects, history and assets](#projects-history-and-assets)); the browser does not use it yet. Running the app shows a test page: a rotating box and a badge that says whether the frontend can reach the backend. Rooms, walking, the minimap and the agent come in later tasks.

The scene document format is defined by the Pydantic models in `backend/app/schema/`. A hand-made example project, `projects/example-l-house/`, holds an L-shaped building with five rooms, a sunken gym reached by two steps, a flat roof, three objects and one photo pin. Tests use it as their fixture.

| Tool | Version | Install (macOS) |
|---|---|---|
| [uv](https://docs.astral.sh/uv/) | recent | `brew install uv` |
| Python | 3.12 (uv manages it) | `uv python install 3.12` |
| Node.js | 22.12+ (or 24 / 26) | `brew install node` |
| GNU Make | any | ships with the Xcode command line tools |

No API keys are needed yet.

## Run the app

1. **Clone the repo and enter it.**
   ```sh
   git clone <repo-url> roomloom
   cd roomloom
   ```
2. **Create your local env file.** Leave the keys empty for now.
   ```sh
   cp .env.example .env
   ```
3. **Start everything.**
   ```sh
   make dev
   ```
   This installs the Python and npm dependencies on the first run (about a minute), and again only when a lockfile changes. Then it starts:
   - the backend (FastAPI) on http://localhost:8000
   - the frontend (Vite) on http://localhost:5173, which forwards `/api` requests to the backend
4. **Open http://localhost:5173 in your browser.** You should see:
   - a dark grey page filling the window
   - a sand-coloured cube slowly rotating in the centre
   - a small badge in the top-right corner reading **`backend: ok`** in green
5. **Stop everything** with `Ctrl-C` in the terminal running `make dev`. Both servers stop. If one server exits on its own (a crash, or a port already in use), `make dev` stops the other one as well. The final `make: *** [dev] Error` line is expected and harmless.

### Optional checks

- **The backend answers directly:** `curl localhost:8000/api/health` prints `{"status":"ok"}`.
- **The proxy works:** `curl localhost:5173/api/health` prints the same thing.
- **The badge reacts to the backend:** stop only the backend, and within 5 seconds the badge turns red and reads `backend: down`. It turns green again once the backend is back. To try this, run the two servers in separate terminals:
  ```sh
  # terminal 1
  cd backend && uv run uvicorn --factory app.main:create_app --reload --port 8000
  # terminal 2
  cd frontend && npm run dev
  ```
- **Interactive API docs** (generated by FastAPI) are at http://localhost:8000/docs.

## Test and lint

```sh
make test   # pytest (backend) and vitest (frontend)
make lint   # ruff, tsc, eslint and prettier --check
```

Both should finish without errors. When Claude Code edits files, a hook (`.claude/hooks/lint-edited.sh`) formats and lints each edited file automatically.

## Regenerate the shared types

The Pydantic models in `backend/app/schema/` are the single source of truth for the scene format. After changing them, run:

```sh
make types
```

This rewrites three generated files (never edit them by hand):
- `shared/scene.schema.json`: the JSON Schema of a scene
- `shared/ops.schema.json`: a placeholder until the ops engine exists
- `frontend/src/types/scene.ts`: TypeScript types, generated from the schema with `json-schema-to-typescript`

Running it twice gives no diff. `make test` fails if the shared schemas are out of date.

## Projects, history and assets

Each project is a folder `projects/<slug>/` (set `PROJECTS_DIR` in `.env` to keep them elsewhere):

```
project.json            name, description, language, ...
scene.json              the current scene, always written atomically
history/index.jsonl     one line per change set: seq, time, source, description, label, scene_version
history/<seq>.json.gz   the full scene right after that change set
assets/<sha256>.<ext>   uploaded photos and textures, stored once per content, never deleted
assets/thumbs/          320 px JPEG thumbnails
thumbnail.jpg           the project-picker image
```

Every change is saved as a full snapshot. Restoring an old change set never deletes anything: it adds a new change set ("Restored to #3"). A project with a scene but no history (like the example project) gets a first "Imported" entry on its first change. While the app runs, the example project gains `history/`, `assets/thumbs/` and `thumbnail.jpg`; git ignores them. Changes to its `scene.json` do show up in `git status`; undo them with `git checkout projects/example-l-house`.

Uploaded photos are turned upright using their EXIF orientation, stripped of all EXIF data (including GPS position), shrunk to at most 4096 px on the long side and saved as JPEG.

Try it with the backend running (`make dev`):

```sh
curl localhost:8000/api/projects                                     # project cards
curl localhost:8000/api/projects/example-l-house/scene               # current scene
curl -F file=@photo.jpg localhost:8000/api/projects/example-l-house/assets   # upload a photo
curl localhost:8000/api/projects/example-l-house/history             # change sets
curl -X POST localhost:8000/api/projects/example-l-house/history/1/restore
curl -X POST -H 'content-type: application/json' -d '{"label": "Before furniture"}' \
  localhost:8000/api/projects/example-l-house/history/1/label
```

Other endpoints: `GET /api/projects/{slug}`, `GET /api/projects/{slug}/assets/{id}` (add `?thumb=1` for the thumbnail), and `POST` / `GET /api/projects/{slug}/thumbnail`. All of them are listed at http://localhost:8000/docs.

## Scene conventions

- Units are metres, and Y is up. A Miro plan point `(x, y)` maps to the world point `(x, 0, y)`. North is −Z, the top of the board.
- Polygons are stored counter-clockwise **as seen from above** (as drawn on the board), without repeating the first point. Wall sides "left" and "right" are as seen from above when walking from `a` to `b`.
- An opening's `sill` and `height` are measured from the higher floor of the two rooms beside its wall.
- A primitive's local origin is its bottom centre, and its front faces local −Z (north at yaw 0).
- Coordinates are rounded to millimetres. `scene.json` is written atomically, with a stable key order.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `Port 5173 is in use` or `address already in use` (8000) | Another dev server is still running. Find it with `lsof -nP -iTCP:5173 -sTCP:LISTEN` (or `:8000`) and stop it. |
| The badge stays `backend: down` | Check the `make dev` output for a backend error, and run `curl localhost:8000/api/health`. |
| uv can't find Python 3.12 | Run `uv python install 3.12`. |
| `npm` complains about the Node version | Upgrade Node to 22.12 or newer. |
| Blank page with no cube | Open the browser console. The page needs WebGL, which every current desktop browser has. |
